# 羽ばたき過多の修正とスマートフォン対応

日付: 2026-10-30。回路は変更なし（sha256 先頭 12 桁 `dc58423c3a0f`）。変更は `web/src/sim/sensing.ts`、`web/src/brain/connectome/encode.ts` と UI・描画側だけ。

## 1. 羽ばたきが止まらない原因

公開版と同じ構成（ハエ人 4 体、NPC 20、車 15）を実際の回路で走らせて測った（`web/scripts/diag-flap.mjs`、ヘッドレス、2 シード x 30 s と 3 シード x 40 s）。

| 測定 | 値 |
|---|---|
| 羽ばたき指令の平均 | 0.25（全 tick）。0.5 超の割合は全時間 24.9%、静かな時（車 30 m 以内なし、NPC・他のハエ人 8 m 以内なし）27.9% |
| チャネルを 0 に固定した時の羽ばたき平均 | lplc2 + lc4: 0.003、lplc1 + lc16: 0.248（変化なし）、ocellar: 0.246（変化なし）、lc4 のみ: 0.167 |
| 平均の刺激量 | lplc2 0.126、lc4 0.072、lplc1 = lc16 0.093 |
| 車が 35 m 以内にいない tick で、最も looming の大きいレイが当たっていた物（looming > 0.05、2605 回） | 静止した建物・小物 100%（車 0、人 0） |
| 静止物のレイの見かけの大きさ（中央値）と拡大 | 140 度（90 パーセンタイル 177 度）、拡大の中央値 0.058 rad/s、99 パーセンタイル 0.26 rad/s |

結論: 原因は lplc2 と lc4。入力は静止した壁・建物の looming。人・NPC・ハエ人ではない。

仕組み:
- 旧式の looming = 接近速度 / 距離 = 1/tau。自分が歩く（約 0.9 m/s）だけで、2.5 m 先の壁は 0.35 /s になる。車が 25 m 先から 8 m/s で来る時（0.32 /s）と同じ値で、見分けられない。
- 脳側の応答は線形でしきい値がない（lplc2 を左右に s = 0.1 与えると羽ばたき 0.15、0.3 で 0.45、0.5 で 0.75。`羽ばたき 0.15` 超で体が羽ばたく）。旧式の `1 - exp(-x)` も小さい x でほぼ線形なので、わずかな刺激でも羽ばたく。
- 街は建物の面が視野の大半を占める。静止物のレイの中央値が 140 度の大きさなのはそのため。

## 2. 変更

- `sensing.ts`: レイごとに、当たった物の見かけの幅 w（車・箱は視線に直交する輪郭、円柱は直径、人 0.6 m）、見かけの角度 `size = 2 atan(w / 2d)`、その増加率 `expansion = w a / (d^2 + w^2 / 4)`（a = 接近速度、正のみ）を追加。
- `encode.ts`: 駆動 `x_i = expansion_i / (1 + (size_i / sizeC)^4)`（視野を埋める物を抑える）の片目の最大に、しきい値のある S 字 `x^2 / (x^2 + K^2)`。lplc2: sizeC 45 度、K 0.25 rad/s。lc4: sizeC 25 度、K 0.4 rad/s。脳（回路・読み出し）は変更なし。
- 式と根拠は `docs/MODEL.md` 8 章。パラメータは設計値で、車の接近と静止物の脇を通る時の分布（調査の記録から）に合わせて置いた。計測結果を見ての再調整はしていない（1 回で基準を満たした）。

注意: 逃避が遅くなった（0.2 s -> 1.7 s）ぶん事故は減っていない（13/20）。車の逃避は羽ばたいて浮くだけで、車を避ける行動ではない（読み出しと体の物理は変更していない）。「静かな時」の定義（車 30 m、NPC 8 m）は計測前に決めた。NPC が近づく時の反応は車ほど強くない（NPC の幅 0.6 m では拡大が小さい）が、測っていない。

`npm run check:behavior` の本体は `--only town` / `--only loom` で単独で回せる。`--only` の時は報告を書かない。本体のスクリプトは、終了しない不具合（最後のワーカーが止まらない）を直して `process.exit` を足した。

## 4. スマートフォン対応

- 性能プロファイル（`web/src/ui/device.ts`）: タッチあり + 画面の短辺 600 px 未満を phone、それ以外で論理コア 4 以下を low、他を full に自動判定。設定タブの「性能」（自動 / 軽量 / 通常）または `?perf=` で上書き（localStorage、切り替えで再読み込み）。
  - phone: devicePixelRatio 上限 1.5、影 1024、ハエ人 3、NPC 8、車 8。low: dpr 2、影 1024、ハエ人 4、NPC 14、車 12。full: 従来どおり（dpr 2、影 2048、4 / 20 / 15）。`?flies= &npcs= &cars=` は優先。
  - 脳 Worker の数: `min(ceil(体数 / 2), 3, floor((コア数 - 2) / 2))`（最小 1）。
  - `[flytown:perf]` の起動行（profile・理由・各数値）と 5 秒ごとの行（profile・dpr 付き）を出す。
- レイアウト（幅 768 px 未満）: 脳パネルは下からのシート。閉じている時はハンドルだけ（ハエ人の名前、前進 %、羽ばたき %）。ハンドルのタップ・ドラッグで開閉（速度と位置で止まる位置を決める）。開くと高さ 60%。ツールバーは常に最下部。ツールのカードを開くとシートは隠れる。カードは 375 px 幅に収まり、高さが足りなければ内側でスクロール。safe-area inset を使用。横スクロールなし。ボタン類は 44 px 以上。
- 操作: タップで選択（タッチは当たり判定を広げた）、何もない所のタップで選択解除（タッチのみ）、1 本指で回転、2 本指でピンチの拡大縮小とパン（OrbitControls の `touches` を明示）、置くツールでは地面のタップで設置（触れた位置に置き場所の印を出す）。2 本指の操作の後は選択・設置しない。iOS のページ拡大（gesture イベント）は止める。

### Browser ペインでの確認（375x812、DPR 2、Android UA 模擬）
- 自動判定: `profile=phone (auto: touch=true short=375px) flies=3 npcs=8 cars=8 dprCap=1.5 shadowMap=1024 workers=2 cores=8`。脳 ready n=3 workers=2。
- シートの閉じた状態・開いた状態、設定タブ、置く / お題のカードのスクリーンショットを確認。`scrollWidth` = 375（横スクロールなし）。ボタン・行の的は 44 px 以上（チェックボックス本体は 22 px だが、ラベルの行が 44 px）。
- マウスのクリックと、合成した PointerEvent（pointerType = touch）で確認: チップで選択、シートの開閉、置くツールで地面をタップするとアイテム +1、2 本指（2 ポインタ）の後は設置されない、ハエ人の近く（中心から 30 px）のタップで選択、何もない所のタップで選択解除。
- デスクトップ幅では従来のレイアウトのまま（右パネル、4 体）。

## 5. 未検証
- iPhone / Android 実機での fps、メモリ（Worker 2 つ + 回路 約 4.4 MB）、発熱、実際の指での操作（ピンチ・回転の感触）。Browser ペインの確認は合成イベントとマウス。実機の性能は測れない。
- Safari 固有（dvh、visualViewport、ステータスバー、ホーム画面追加）、横向き（幅 768 px 以上になる端末は PC 向けレイアウトになる）、iPad。
- 静止物の脇を通る時のしきい値が、お題（道路を渡る、パン屋）の難易度にどう効くか。NPC やハエ人どうしの接近での反応。
- 逃避の後に車を実際に避けられるか（事故 13/20 のまま）。
- 実際のブラウザ（Worker 経由、1〜数 tick の遅れあり）での羽ばたき割合の再測定。Browser ペインが非表示だと描画ループが止まるので、今回はヘッドレスの数値のみ。
