# M2 報告: JS 脳（発火率モデル・可塑性・Worker）

日付: 2026-10-29

## 作ったもの
- `web/src/brain/connectome/`
  - `circuit.ts`: circuit.bin / meta.json の読み込み（重みは Float32Array のまま、バッファのコピーなし）。
  - `model.ts`: MODEL.md 2〜5 章のモデル。状態 r, d は float64、重みは共有。CSR の積を 1・2・4 体まとめて行うカーネル（行列の index/weight 読みと足し算の連鎖を体の間で共有、1 体あたり約 1.8 倍速）。1 ステップの配列確保なし。phi は x < 2.5 で tanh の 13 次級数、それ以上で 1 - 2/(exp(2y)+1)（Math.tanh より速い、誤差 1e-10 以下）。駆動のない r は 1e-20 未満で 0 に落とす（非正規化数対策）。
  - `readout.ts`: 6 章の読み出し（`readoutCommands` の 1 関数、係数は meta.readout）。BodyCommand への合成は `toBody`（forward - backward、flap = max(flap, escape)）。
  - `encode.ts`: SensorFrame -> 19 チャネルの左右刺激量。対応表は MODEL.md 8 章。
  - `batch.ts`: 複数体の脳（雑音: 感覚ニューロン 2,521 個にシード付き N(0, 0.05²)、ドーパミン注入、暖機、好みの探り、出力パッキング）。
  - `worker.ts` / `protocol.ts` / `hub.ts`: Worker と窓口。`ConnectomeHub`（Worker 数は 2 体に 1 つ、最大 3）、`ConnectomeBrain`（BrainAgent 実装、`inject(kind, dose, durationMs)`、`getPreference()`、`getConnectomeDebug()`、`getDebug()`）。
- `web/src/sim/sim.ts`: `SimOptions.brainFactory` を追加（既定の脳）。`web/src/main.ts`: ハブを作り全ハエ人に接続。ManualBrain は DEV トグルのままで、切ると既定の脳へ戻る。`?brain=off` で脳なし（指令 0）。`brain/types.ts`: `BrainDebug.extra` を追加。
- `web/scripts/`: `parity.mjs`（`npm run verify:parity`）、`bench-brain.mjs`（`npm run bench:brain`）、`check-brain.mjs`（動作確認、node 直接実行）。`package.json` に 2 スクリプト追加。
- `docs/MODEL.md` に 8 章を追記（他の章は未変更）。

## 一致試験（verify:parity、node 24、float64）
| 項目 | 最大絶対誤差 |
|---|---|
| 発火率（300 ステップ x 13 群） | 4.5e-13 |
| step 0 の r / d | 0 / 0 |
| step 100 の r / d | 1.3e-11 / 8.1e-14 |
| step 300 の r / d | 2.1e-11 / 2.0e-12 |
| 5 体を 4+1 のブロックで同時に進めた結果と 1 体の差 | 0 |
合格条件 1e-6 に対し 4 桁以上の余裕。合格。級数近似に替える前（Math.tanh）は 4e-16〜6e-15 だった。

## 動作確認（check-brain.mjs）全て合格
- 暖機後の無刺激: z が 0 付近、forward = 0.498（V0 = 0.5）。
- 可塑性: fruit 匂い + ご褒美を 3 回対提示 -> fruit の好み 0.114 -> 0.164（学習していない体は 0.114 のまま）。対照の vinegar は 0.011 しか動かない。d の最小 -0.95（下限 -1 内）。
- ドーパミン: reward で PAM 群 0.083 -> 3.92、punish で PPL1 群 0.089 -> 4.64。
- looming（lplc2 = 1）で flap 0 -> 1.0、forward 0.50 -> 0.78。

## 速度（bench-brain.mjs、M1 Mac）
測定中、マシンの負荷平均が 6〜15（他プロセスが 3〜4 コア占有）で、数値は大きく揺れた。同じ条件で再現しない。静かな時間帯に得た最良値と、負荷中の値を分けて書く。
- 静かなとき（探りなし、1 ワーカー）: 1 体 3.4 ms、4 体 9.8 ms、6 体 16.8 ms /ステップ（1 体あたり約 2.7〜3.5 ms。SpMV 約 55%、phi 約 25%）。
- 探り（既定 2 秒周期）あり: 約 +25〜50%。6 体 1 ワーカーだと 20 ms 前後で、予算ぎりぎり。
- 3 ワーカー（node worker_threads、6 体、探りあり）: 平均 13.8 ms、p95 17.4 ms（負荷中の 1 回）。4 体 3 ワーカーは負荷中で 22.6 ms と悪化した（コアが空いていないため）。
- 負荷中の 1 ワーカー 6 体: 平均 40〜60 ms。合格とは言えない。
- 判定: 静かなマシンで 6 体・3 ワーカーなら 20 ms 以内の見込みだが、今回の環境では「全構成で p95 < 20 ms」を確認できていない（bench スクリプトは未達なら FAIL と表示する）。
- 取った最適化: 複数体まとめの SpMV、phi の級数化、非正規化数の除去、探りを各 tick に均して遅れ時に止める、体を複数 Worker に分割。float32 計算は SpMV で効果がなかったので使っていない（パリティ経路と同じ float64 のまま）。

## ブラウザでの確認（dev サーバ 5173、Browser ペイン）
- Worker が回路を読み込み（22〜214 ms）、暖機（体 2 つで約 4 秒、負荷中）して `ready` を出す。ゲームの Sim と接続して 500 tick 実行し、命令・脳パネル用の活動・好みが返ることを確認。
- アプリ本体（render 修正後）も起動し、sim_t が進み、ハエ人 1〜3 が ConnectomeBrain で動く。負荷中（fps 15）で `[flytown:brain] lag` が出る。lag の報告機構は動作確認済み。
- 描画の負荷が高く（fps 15）、本来の速度での長時間走行は未確認。

## 未検証・注意
- 負荷のないマシンでの速度。ブラウザの Worker 3 本同時の実速度。
- 暖機（体 2 つで約 1〜4 秒）の間は指令 0（ハエ人が止まっている）。
- ゲームのセンサ（StubField）をそのまま入れると、dry = 1（StubField の humidity = 0）が左右対称なのに turn -0.38（細胞数の左右差による偏り）、ocellar（日向 light 1 -> 0.5）が groom 0.37 を常に出す。アブレーションで確認（dry を切ると turn -0.03、ocellar を切ると groom 0）。M4 の Field 実装で humidity を中立にする、または ocellar の写像（日向を基準にした差分など）を決める必要がある。設計判断なので既定のまま残した。
- 好みの探り（pref）の尺度 `tanh(差 / 1.0)` は暫定（vinegar -0.93、cva 0.64、他 0.1〜0.2）。MBON の価値割り当て（ACh +1、Glu -1）は consult/003 のまま未検証。
- `odor.smoke` に対応する入力チャネルは無く、`water` は Field に量が無いため 0。
- 追いつけないときは tick を落とさずためる（500 tick = 10 秒を超えたら捨てて報告）。
